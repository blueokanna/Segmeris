# Rust 下载恢复契约

Rust 的公开 FRB 下载 API 和 `ProgressUpdate` 字段保持不变。默认并发为 6；显式设置为 1 时，音视频也按顺序下载。

## 调用端必须保存的内容

- 保存原始页面 URL、选中候选的清晰度/编码/尺寸/协议/音轨选择、RequestContext、下载选项和**原输出路径**。
- 应用重启后重新分析原页面，匹配原来的表示和音轨，再传入新的媒体 URL 与备用 URL。找不到匹配表示时应报告，不能直接选第一条候选继续旧任务。
- 使用相同输出路径重新调用 `download_media_with_context` 即触发恢复检查。不要因为恢复而生成新的文件名或输出目录。
- `set_download_paused` 使用调用时的原输出路径；暂停只控制当前进程内的任务。重启后的任务状态、重新发起下载由调用端负责。
- 下载失败不应删除 Rust 的缓存目录。`keep_temp=false` 表示成功发布成品后清理缓存，不表示失败时删除。

## 目录与身份

普通媒体与 DASH 缓存位于输出目录下的 `.segmeris-<stem>-<identity>`。输出父目录会规范化，避免 `./`、相对/绝对路径与父目录符号链接形成并发写入别名。HLS 使用与输出关联的稳定目录；Android HLS 优先使用应用 files 目录，避免系统 cache 清理。

Bilibili 已知 `*.bilivideo.com` / `*.bilivideo.cn` 的 `/upgcxcode/` 对象，可以跨签名刷新和官方镜像复用：身份只忽略实现中列明的授权/跟踪参数，保留对象路径及其余查询参数。其他站点保留完整 URL 身份，不任意剥离查询参数。请求头仍参与 partial 身份，变更授权上下文可能安全地重新下载。

目录匹配并不等于直接信任字节：

- 顺序 partial 继续前发送 `If-Range`，校验响应实体、状态、范围和总长度；服务器返回完整新实体时先废弃旧 partial，再持久化新标识。
- 并行块为固定 4 MiB。实际探测确认 Range、强 ETag 和至少 8 MiB 总长后才启用。每块都有独立 partial，完整块通过长度与 SHA-256 校验后发布。变化的 ETag/长度会隔离旧块；不允许错误的 200/206/Content-Range 拼入原文件。
- 并行被 CDN 拒绝时，等待工作线程结束，保留连续有效前缀并降为单连接恢复。
- 完成的音视频输入还要通过源身份、本地长度/哈希和远端 validator 检查，不能仅凭“非空文件”复用。
- HLS 仅复用完整、哈希正确且 URI/范围/序号/密钥/初始化内容身份吻合的分片。刷新后资源 URI 不一致的分片会重新下载；不会为了命中缓存而泛化剥离 HLS 签名参数。

## 并发、内存与速度

分离音视频共用并发预算：默认 6 为视频最多 5 路 Range 加 1 路音频。普通媒体可以使用全部预算；不支持安全 Range 的服务使用流式单连接。

HTTP 媒体缓冲为每请求 64 KiB，Range 块直接落盘，不在内存保留 4 MiB 对象。HLS 正文和 AES-CBC 解密也流式落盘；初始化段仍有既有的总缓存上限。实际进程内存还包括线程、TLS、初始化段和媒体后处理，不是固定 RSS 保证。

进度消息中的速度由本次新接收字节与实际经过时间计算，排除预先缓存的字节；不会用百分比反推下载速度。该数值包括相应传输的等待时间。音视频分别报告，不是全任务聚合吞吐。

## 成品发布与边界

direct、DASH 和 HLS 转换写入唯一的同目录 staging 文件，媒体校验、同步完成后以一次 rename 替换最终输出。失败不会提前覆盖旧成品。桌面正常错误返回时自动清理 staging。

移动端原生转换超时仍可能留下未结束的 native 操作；唯一 staging 路径可阻止它覆盖新任务的最终文件，但不能代替 native cancel/join。超时 staging 会保留，不应在 native 操作仍存活时删除相关输入。当前控制 API 只提供暂停/恢复，没有端到端取消协议。网络沿用现有 socket 超时，未承诺所有慢速响应都有绝对总时限。

## 验证

新增确定性回归覆盖异常退出后新调用续传、短响应保留、实体变化、完成输入哈希校验、Bilibili 签名身份、错误范围/状态、Range 真并发与预算、并行降级、HLS 大对象/忽略 Range/AES padding，以及成品保护。

已通过本地公开 Bilibili 测试 `BV1GJ411x7h7`（匿名，640×360 视频加音频，成品 5,289,454 字节）及本地 FFmpeg 三段 fMP4 HLS roundtrip（约 18 秒、180 帧）。实网测试包含解析和后处理，其耗时不是纯下载带宽基准。
